            Cheat sheet

            read this right before the quiz

            Keys

            PK = unique + minimal, by what a row means (participant_id, method, trial). FK = must match a PK in another table (OrderItems.order_id → Orders).

            Operations

            σ selection = rows = WHERE. π projection = columns = SELECT, drops duplicates. ⋈ join drops rows with no match (book 105 → still 4 rows). γ = GROUP BY.

            Anomalies

            Update: a fact in many rows gets two versions. Insert: can't add an author without a book. Delete: deleting the only book loses the author. Fix = normalize (one entity per table).

            OLTP vs OLAP

            OLTP: transactions, row storage, normalized, INSERT/UPDATE. OLAP: analysis, column storage (read only the columns you need), star schema, SELECT + GROUP BY. Warehouse: subject-oriented, integrated, non-volatile, time-variant.

            Star schema

            Fact = events: measures (revenue, qty) + FKs, tall. Dimension = things: labels (title, genre, city), wide, denormalized. Grain = one book in one order. Snowflake = normalized dimensions, more joins.

            OLAP operations

            Slice fixes one dimension. Dice fixes several. Drill down = finer (city → stations, quarter → month). Roll up = coarser. Pivot = swap rows/columns.

            ETL vs ELT

            ETL cleans before loading, on its own server. ELT loads raw first, transforms inside the warehouse (dbt): raw → cleaned → modeled. ELT is today's default.

            Search

            Linear: O(n), no sorting. Binary: O(log n), needs sorted data; 1M items ≈ 20 checks, 100 ≈ 7. Sort once pays off after about log₂N searches (databases: indexes).

            Big-O

            Keep the biggest term, drop constants: 3n² + 100n + 50 → O(n²); 5 → O(1). Order: 1 < log n < n < n log n < n² < 2ⁿ. A loop with list.count or x in list inside = O(n²).

            Array vs linked list

            Array: read by index O(1), insert/delete in the middle O(n) (shift). Linked list: read by index O(n) (follow pointers), insert/delete O(1) once you're there. Search by value: both O(n).

            Hash table

            Key → slot, lookup O(1) average, O(n) worst (collisions). No sorted order, so no range queries. set, dict, groupby, merge. 1,000 checks in a 1M list = 1 billion comparisons; a set ≈ 1,000.

            Stack, queue, BST

            Stack LIFO (push/pop, O(1), DFS, undo). Queue FIFO (enqueue/dequeue, O(1), BFS). BST: left smaller, right larger; O(log n) only if balanced, sorted inserts make it a linked list, O(n).

            BFS and DFS on the practice graph, from A

            BFS (queue, level by level) = A, B, D, C, E, G, H, F. DFS (stack, push neighbors reversed, go deep) = A, B, C, E, H, F, G, D. On a graph, mark nodes explored so cycles don't loop forever.

            Inferential statistics

            How a sample lets you say something about a whole population, and how sure you can be.

            L5 · 01

            From a sample to a population

            Descriptive statistics summarize the data you have. Inferential statistics use that data to say something about a bigger group you never fully measure. A number describing the whole population is a parameter, like the population mean μ ("mu"), which is usually unknown. A number computed from your sample is a statistic, like the sample mean x̄ ("x-bar"). n is the sample size.

            Who is in your sample?

            In this simulation the classroom only contains commuters (the long right cluster). Repeat the random sample a few times: it wobbles around μ. The classroom sample is consistently too high, and making it bigger does not fix that.

            Remember

            • Descriptive: "here is what happened." Inferential: "here is what we can infer."
            • Every method in Lecture 5 assumes a random sample from the population you care about.
            • A bigger sample (larger n) from a biased source just gets you a more confident answer that is still wrong.

            Common mistake

            The class's average commute (42 min) describes students like the ones in that class (one upper-level IS section), not necessarily all NJIT students. No calculation later in the lecture can fix a sample that was not random.
            L5 · 02

            Probability as area, and the normal curve

            For values like times and scores, you ask about ranges. The probability of a range is the area under the density curve over that range, and the total area is 1. A normal curve is set by two numbers: the mean μ (center) and the standard deviation σ (spread). The z-score z = (x − μ) / σ says how many σ a value sits from the mean.

            Remember

            • 68–95–99.7: share of values within 1, 2 and 3 standard deviations (SD, σ) of the mean. The exact 95% cutoff is 1.96σ. Remember 95% and 1.96: they come back in concepts 05 and 10.
            • The curve's height is not a probability. Only area is.
            • |z| > 3 happens only 0.3% of the time, which is why Lecture 3 used it to flag outliers.
            • Most real variables are not normal: taxi fares, commutes and incomes are right-skewed. Concept 03 explains why normal-based tests still work.

            Common mistake

            "Above 90" is one tail only. 5% falls outside ±2σ in total, so only about 2.5% is above 90 (exactly 2.28%).
            L5 · 03

            The Central Limit Theorem

            Take a sample of size n, compute its mean, and repeat many times. Even when the population is skewed, those sample means pile up into a roughly normal shape centered on μ. The pile gets narrower as n grows.

            Sampling from a skewed population

            Remember

            • The CLT gives the shape of the sampling distribution: normal.
            • It is centered on the population mean μ, not the median.
            • Its spread is σ/√n, the standard error (next concept).
            • With about 30+ values per sample, moderate skew is fine. Small and skewed data needs different tests (concept 08).

            Common mistake

            The CLT is about the distribution of sample means. The raw data stay just as skewed as before.
            L5 · 04

            Standard error

            The standard error measures how much a statistic would bounce around if you repeated the study with the same sample size. For a mean, SE = s / √n, where s is the standard deviation of your sample and n is the sample size. The square root makes precision expensive: to halve the SE you need four times the data.

            SE shrinks as n grows (s = 10)

            SE–
            Last change–

            Remember

            • SD describes how spread out individual values are. SE describes how spread out the sample mean is.
            • Taxi fares: SE is $1.16 with 100 rides, so $0.58 with 400 rides.
            • The Central Limit Theorem (CLT) gives the shape and the SE gives the width. Together they power every test in this course.

            Common mistake

            Doubling n does not halve the SE. It divides it by √2, about 1.41.
            L5 · 05

            The 5-step hypothesis test

            A hypothesis test asks one question: if nothing were going on, how surprising would my data be? You assume "no effect" (H₀), measure how far your data land from it, and reject H₀ only if that result would be rare.

            The steps, in order

            1. 1
              Formulate hypotheses

              H₀ says there is no difference and always uses "=" (μA = μB). H₁ says there is one: "≠" for a two-tailed test. This course always uses two-tailed tests.

            2. 2
              Choose α

              The significance level, usually 0.05. Confidence level = 1 − α = 95%. Choose it before looking at the data.

            3. 3
              Choose the test and compute the statistic

              The statistic (t, z, χ²) measures how far the sample is from what H₀ predicts.

            4. 4
              Find the p-value

              The probability of a result this extreme or more extreme, assuming H₀ is true.

            5. 5
              Decide

              p ≤ α: reject H₀. Otherwise: fail to reject H₀. You never "accept" H₀.

            Is this coin fair? 100 flips

            H₀: P(heads) = 0.5
            p-value (two-tailed)–
            Decision at α = 0.05–

            The bars show how often each count happens with a truly fair coin. Red bars are results at least as far from 50 as yours, in either direction. Their total height is the p-value. The slide's example of 85 heads is astronomically unlikely, so you reject "fair".

            Remember

            • H₀ is the "no effect" assumption, so it always gets the equals sign. Never write H₀: μA ≠ μB.
            • Reject H₀ → the groups differ, and the means tell you which direction.
            • Fail to reject → no statistically significant evidence of a difference. That is not proof there is none; the sample may be too small.

            Common mistake

            With α = 0.05 and p = 0.12 you fail to reject H₀. You may not conclude the two designs are the same.
            L5 · 06

            The t-statistic and the p-value

            A t-statistic is signal ÷ noise: the difference in means divided by its standard error. A bigger difference or less noisy data gives a bigger t. You then check where t lands on the t-distribution for your degrees of freedom (df = n − 1 for one sample or paired data). Small samples have heavier tails, so they need a bigger t to reject.

            • p-value = area under the t-curve beyond ±|t|. α = the total red area you agreed to call "too rare".

            Common mistake

            A p-value is not the probability that H₀ is true. It is computed by assuming H₀ is true.
            L5 · 07

            Type I and Type II errors

            Every decision can be wrong in two ways. A Type I error rejects a true H₀ (a false positive), and you set its rate up front with α. A Type II error misses a real effect (a false negative). Its rate, β, depends on how big the real effect is and how much data you have.

            • Larger α → more false positives, fewer false negatives.

            Common mistake

            "Not significant" often just means low power. An underpowered study can easily miss a real effect.
            L5 · 08

            Which test do I use?

            Three questions pick the test: what type of data, how many groups, and are the same people measured twice. This course works with the three t-tests for comparing means; the others are on the map so you can recognize them.

            Test picker

            1 · What are you measuring?
            2 · How many groups?
            3 · Same people measured in both conditions?

            Practice: name the test, then open to check

            Remember

            • One-sample t: one group vs. a known value.
            • Paired t: the same people in two conditions. It works on each person's difference, which should be roughly normal.
            • Independent t: two different groups that are otherwise alike. Use the unequal-variances (Welch) version by default.

            Common mistake

            Before/after on the same customers is paired. Before/after where the "before" is only a known average is one-sample.

              L5 · 10

              Confidence intervals

              A confidence interval is a range of plausible values for a parameter: x̄ ± t* × SE. A 95% CI holds exactly the null values that a two-tailed test at α = 0.05 would not reject. That makes it a test and an effect-size estimate in one picture.

              What "95%" actually means

              Each line is one study's 95% interval. Red ones missed the true μ. Over many studies about 95% catch it. Any single interval either contains μ or it doesn't.

              CI ↔ hypothesis test

              H₀ says the mean difference is 0. If 0 is outside the 95% CI, reject at α = 0.05. If 0 is inside, fail to reject.

              Back to our commutes

                Remember

                • 95% describes the procedure: across repeated samples, about 95 of 100 intervals contain μ.
                • Two group CIs that don't overlap → significant. If they overlap, the result is ambiguous: check the CI of the difference.
                • For paired data (like concept 09), use the CI of the differences, not two separate group CIs.
                • CIs show the plausible size of the effect, which is often more useful than p alone.

                Common mistake

                "There's a 95% probability μ is in this interval" is wrong. The 95% is the long-run hit rate of the method.

                Visualization

                Why we plot data, how perception reads a chart, and how to choose one that answers the question honestly.

                L4 · 12

                Why visualize: Anscombe's quartet

                These four datasets have the same means, the same variances and the same correlation. Plotted, they are completely different: a noisy line, a curve, a perfect line with one outlier, and a vertical stack held up by a single point. Summary statistics can be too reductive.

                Why visualize

                • Statistics can hide shape. Look at the data, not only the numbers.
                • You can explore data before you know which question to ask.
                • A chart acts as external memory: you compare by looking instead of holding numbers in your head.
                • Three uses: exploration (generate hypotheses), confirmation (check them), communication (present them).

                The bar to clear

                At the very least, a visualization should be more effective than a table.
                L4 · 13

                Marks and channels

                Marks are the shapes that stand for data: points, lines, areas and bars. Channels are the visual properties that carry the values: position, length, angle, area, color, shape. Your eyes read some channels far more accurately than others, so the channel you pick decides how well people can compare.

                • Bar chart: mark = bar, channel = length. Scatter plot: mark = point, channels = horizontal and vertical position.
                • Match the channel to the data type: magnitude channels for ordered values, identity channels for categories.

                Pie charts use angle, which is hard to compare. Close slices, and especially several pies side by side, are where they fail. Bars on a shared axis are almost always better.
                L4 · 14

                Start from the question

                Don't start with a chart type. Start with the question you're asking, then pick the mark, the channel, and finally the chart.

                What is your question?

                Exploratory vs explanatory

                • Exploratory: you are still looking for the story. Many views, filters, detail.
                • Explanatory: you are presenting a finding. Few variables, one message per chart, focus on what answers the question.
                • Presentations are usually explanatory. Dashboards default to explanatory but add filters to drill down.

                For share of total, use sorted or stacked bars, not a pie. For three variables, use color or size on a scatter plot, or small multiples, not 3D.

                Data management

                How a business stores its records so they stay correct, and how it reshapes them into a warehouse so analysts can ask questions fast.

                L6 · 18

                Relations, primary keys and foreign keys

                A database management system (DBMS) such as MySQL, PostgreSQL or SQLite enforces rules, handles many users at once and answers queries. In a relational database every table is a relation: each row is a tuple, each column an attribute, and the allowed values of a column are its domain. A primary key (PK) is the smallest set of columns that identifies every row. A foreign key (FK) is a column whose values must match a primary key in another table, and that is what links tables.

                Find the primary key

                click column headers to add or remove them from your key
                Pick one or more columns.

                Remember

                • Two rules for a primary key: unique (no two rows share it) and minimal (drop any column and it stops being unique).
                • A key can be one column (order_id) or a combination (participant_id, method, trial).
                • The DBMS rejects any INSERT that would duplicate a key. No two rows in a relation can be identical.
                • An FK is the PK of another table copied into this one: OrderItems.order_id → Orders.order_id. One order has many items.

                Common mistake

                Picking a column because it happens to be unique in the rows you can see. time_seconds has no repeats here, but two trials could take 8.33 s. A key comes from what a row means (one participant, one method, one trial), not from luck in the sample.
                L6 · 19

                Relational algebra: the operations behind SQL and pandas

                Relational algebra is algebra on tables. Each operator takes tables in and gives a table out (the closure property), so you can chain them. The six primitive operations are selection σ, projection π, union ∪, set difference −, Cartesian product × and rename ρ; together they can express any relational query. The five you will use most are selection, projection, join, union and grouping with aggregation.

                Run an operation on Books

                green rows are kept, faded columns are dropped

                Remember

                • σ selection filters rows (SQL WHERE, pandas df[df.genre == 'Fiction']). Columns stay the same.
                • π projection keeps columns (SQL SELECT title, genre, pandas df[['title','genre']]) and, in algebra, removes duplicate rows.
                • γ grouping collapses rows that share a value into one row per group, with COUNT, SUM or AVG. It is an extension: SQL, pandas and pivot tables add it to the original algebra.
                • A relation is a set of tuples: no duplicates and no order. SQL keeps duplicates unless you write SELECT DISTINCT.

                Common mistake

                Mixing up the Greek letters. σ (sigma, "s" for select) works on rows; π (pi, "p" for project) works on columns. In SQL the confusion is worse: the SELECT keyword is actually projection, and selection lives in WHERE.
                L6 · 20

                Redundancy, the three anomalies and normalization

                When one table stores facts about two things, like books and their authors, the author's details repeat on every book row. That redundancy causes three anomalies. Normalization splits the table so each table describes one entity and each fact is stored once, then links the tables with keys.

                Break it, then fix it

                try each change on both designs
                Pick a change above.

                Remember

                • Update anomaly: one fact lives in many rows, so an update that misses a row leaves two different versions.
                • Insert anomaly: you cannot store a fact (a new author) until an unrelated fact (a book) exists.
                • Delete anomaly: deleting one fact (the only Munro book) erases another (Munro herself).
                • Normalization's payoffs: less redundancy, better integrity (change data in one place) and easier maintenance.

                Common mistake

                Thinking normalization loses information. Nothing is thrown away: author_id in Books points to the author row, and a join (next concept) rebuilds the wide table whenever you need it.

                OLTP vs OLAP, and why warehouses store columns

                Relational databases are tuned for OLTP (online transaction processing): many short reads and writes of single rows, such as placing an order or a bank transfer. Running big analytical queries on that same database scans tables the app is writing to and slows customers down. A data warehouse is a separate, read-optimized database tuned for OLAP (online analytical processing). It is subject-oriented, integrated, non-volatile (history is kept) and time-variant (every fact is timestamped), and it usually stores data by column.

                Star schema: fact tables, dimension tables and grain

                A star schema has one central fact table surrounded by dimension tables. The fact table holds the numbers you analyze (revenue, qty) plus a foreign key to each dimension. Dimensions hold the labels you filter and group by (title, genre, city, month). The grain is what one row of the fact table represents. Here it is one book in one order.

                  Remember

                  • Fact table: one row per event, numeric measures + foreign keys, tall and narrow, grows with every event.
                  • Dimension table: one row per thing (book, customer, day), descriptive attributes, short and wide, denormalized on purpose (author_name is copied into DIM_BOOK).
                  • Each dimension's key is its finest-detail attribute (the day, date_id), and that key is the FK in the fact table.
                  • Store the finest (atomic) grain you can: you can always roll up later, but you can never split a coarse row back apart.

                  Common mistake

                  Putting a book's list price in the fact table. It describes the book, so it belongs in DIM_BOOK. The fact is revenue, what the customer actually paid on that line (qty × price). And the fact table's PK is item_id: (date_id, book_id, cust_id) is unique in the sample, but one customer can buy the same book twice in a day in two orders.

                  Linear search vs binary search
                  
  
                  Linear search checks each element from the start until it finds the target or reaches the end. Binary search uses divide and conquer: look at the middle element; if it's the target you're done, if the target is smaller search the left half, if larger the right half, and repeat. Each check throws away half of what is left, so it needs about log₂(N) checks, but only on sorted data.

                  Sort once, search many
                  
  
                  Binary search is only fast after you pay to sort. Sorting with merge sort takes about N log₂ N steps, then each search takes log₂ N. With k searches on N items, binary wins when k · N > N log₂ N + k log₂ N, that is k > N log₂ N / (N − log₂ N). For large N the rule of thumb is k ≈ log₂ N.

                  Big-O notation
                  
  
                  Big-O describes how an algorithm's running time (or memory) grows as the input size n grows. It is an upper bound: O(n²) means the cost grows no faster than n². In this course it describes the worst case. To find it, keep the dominant term and drop the constants: for large n the biggest term swamps the rest.

                  Remember
                    
      
                  • Fastest to slowest: O(1) read by index · O(log n) binary search · O(n) linear search · O(n log n) merge sort · O(n²) nested loops · O(2ⁿ) brute-force subsets.
                    • 
      
                  • O(1) and O(log n) are excellent; O(n) and O(n log n) are fine for most tasks; O(n²) gets painful past n ≈ 10,000; O(2ⁿ) works only for very small n.
                    • 
      
                  • Big-O says how cost grows, not how big it is. Summing a million doubled numbers is O(n) both ways, but a Python loop takes ≈ 30 ms and NumPy ≈ 1 ms, because NumPy runs the loop in compiled code over a contiguous array. In pandas, use column operations instead of row loops or .apply.

                  Common mistake
                  Thinking a constant means "fast." A function that always takes 100 steps is O(1): constant, just slow. And 3n² + 100n + 50 is O(n²) even though 100n is bigger when n is small. Big-O is about what happens as n gets large.

Because you only ever touch an end, every operation is O(1).

                  Trees and binary search trees
                  
  
                  A tree is a hierarchy of nodes connected by edges: a connected graph with no cycles and n − 1 edges for n nodes. The root has no parent, a leaf has no children, depth is the distance from the root and height is the longest path to a leaf. In a binary search tree (BST) each node has at most two children, every value in the left subtree is smaller and every value in the right subtree is larger. A balanced BST is binary search stored as a tree: the root plays the middle element, and each step down throws away half of what's left.

                  Breadth-first and depth-first search
                  
  
                  Traversal means visiting every node in a defined order. BFS visits all nodes at depth 1, then depth 2, and so on, using a queue. DFS dives as deep as it can down one branch before backtracking, using a stack. The data structure decides the order. Both work on trees and on general graphs, which can have cycles and directed edges; on a graph you must mark nodes as explored so you don't loop forever.

                  procedure BFS(G, root):
    let Q be a queue
    label root as explored
    Q.enqueue(root)
    while Q is not empty:
        v = Q.dequeue()
        for w in G.neighbors(v):
            if w is not explored:
                label w as explored
                Q.enqueue(w)
                  
      
                  DFS (push neighbors in reverse)
                  procedure DFS(G, root):
    let S be a stack
    S.push(root)
    while S is not empty:
        v = S.pop()
        if v is not explored:
            label v as explored
            for w in reversed(G.neighbors(v)):
                if w is not explored:
                    S.push(w)

                    •

                    •

Both are valid depth-first orders, but only the reversed one matches "alphabetical first."
